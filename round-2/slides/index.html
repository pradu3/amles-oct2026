Why Clinical Trials?

The Scale

  • 500 000+ studies registered worldwide
  • Covers 220+ countries
  • Updated daily via public API
  • Free, well-documented, real data

The Problem

  • ~30% of trials fail due to enrollment issues
  • Dropout costs $600M+ per failed Phase III trial
  • Predicting dropout early saves lives & resources
  • Perfect use case for in-database ML

Source: JAMA Internal Medicine, 2023 / Tufts CSDD

ClinicalTrials.gov API

Public REST API — no authentication required

click to explore the parameters →

Base URL All v2 requests start here. Returns JSON with a studies array. The v1 API was retired in 2024.
query.cond Condition or disease. Accepts MeSH terms, free text, or synonyms — e.g. alopecia, type 2 diabetes, "heart failure"
filter.overallStatus Study lifecycle stage: COMPLETED · RECRUITING · ACTIVE_NOT_RECRUITING · TERMINATED
filter.phase Trial phase: EARLY_PHASE1 · PHASE1 · PHASE2 · PHASE3 · PHASE4 · NA
fields Comma-separated module names. Limits payload — only fetch what you need. Omit to get all ~40 fields per study.
pageSize Max 1000 per page. Response includes nextPageToken — pass it as &pageToken=… to fetch the next page. 

# Base URL (v2)
https://clinicaltrials.gov/api/v2/studies

# Fetch 10 completed Phase 3 alopecia trials
GET /api/v2/studies
  ?query.cond=alopecia
  &filter.overallStatus=COMPLETED
  &filter.phase=PHASE3
  &fields=identificationModule,statusModule,designModule,eligibilityModule
  &pageSize=10
JSON response Pagination via nextPageToken ~500k studies

REAL_VECTOR and Embedding Models


-- Create a table with a vector column
CREATE TABLE TRIAL_EMBEDDINGS (
    NCT_ID    VARCHAR(20) PRIMARY KEY,
    EMBEDDING REAL_VECTOR(768)
);

-- Bulk-embed using INSERT ... SELECT with VECTOR_EMBEDDING()
-- Runs entirely inside HANA — no data leaves the database
INSERT INTO TRIAL_EMBEDDINGS (NCT_ID, EMBEDDING)
SELECT NCT_ID,
       VECTOR_EMBEDDING(CRITERIA_TEXT, 'DOCUMENT', 'SAP_GXY.20250407')
FROM CLINICAL_TRIALS
WHERE CRITERIA_TEXT IS NOT NULL
  AND CRITERIA_TEXT != '';

SAP_GXY.20250407 is a SAP-provided multilingual embedding model (768 dims, 512 token default limit) available on HANA Cloud instances with Script Server enabled.

Docs: HANA Cloud Vector Engine Guide

Semantic Similarity Search


-- Find trials semantically similar to a free-text query
-- Step 1: embed the query string inline
-- VECTOR_EMBEDDING(text, 'DOCUMENT', model_id) → REAL_VECTOR
SELECT TOP 10
    NCT_ID,
    COSINE_SIMILARITY(
        EMBEDDING,
        VECTOR_EMBEDDING(
            'elderly patients with heart failure and diabetes',
            'DOCUMENT',
            'SAP_GXY.20250407'
        )
    ) AS SIMILARITY
FROM TRIAL_EMBEDDINGS
ORDER BY SIMILARITY DESC;
Use case: an LLM agent translates a natural-language question into a query string, embeds it inline, and retrieves semantically relevant trials — no keyword matching needed.

Embeddings from Python


# Use a cursor to run the INSERT ... SELECT directly from Python
cursor = cc.connection.cursor()
cursor.execute("""
    INSERT INTO TRIAL_EMBEDDINGS (NCT_ID, EMBEDDING)
    SELECT NCT_ID,
           VECTOR_EMBEDDING(CRITERIA_TEXT, 'DOCUMENT', 'SAP_GXY.20250407')
    FROM CLINICAL_TRIALS
    WHERE CRITERIA_TEXT IS NOT NULL
      AND CRITERIA_TEXT != ''
""")
cc.connection.commit()
cursor.execute("SELECT COUNT(*) FROM TRIAL_EMBEDDINGS")
print("Embedded rows:", cursor.fetchone()[0])
cursor.close()

All computation runs inside HANA — no text is sent to Python over the wire. Python only sends the call and receives confirmation — no text is serialised over the wire.

-- 1. Parameter table (controls the algorithm)
CREATE LOCAL TEMPORARY COLUMN TABLE #PAL_PARAM_TBL (
  "PARAM_NAME"   NVARCHAR(256),
  "INT_VALUE"    INTEGER,
  "DOUBLE_VALUE" DOUBLE,
  "STRING_VALUE" NVARCHAR(1000)
);
INSERT INTO #PAL_PARAM_TBL VALUES ('ITER_NUM',    200,  NULL, NULL);
INSERT INTO #PAL_PARAM_TBL VALUES ('ETA',         NULL, 0.05, NULL);
INSERT INTO #PAL_PARAM_TBL VALUES ('MAX_DEPTH',   4,    NULL, NULL);
INSERT INTO #PAL_PARAM_TBL VALUES ('SPLIT_METHOD',NULL, NULL,'histogram');

-- 2. Output table (receives the trained model)
CREATE COLUMN TABLE MODEL_TBL (
  "ROW_INDEX"     INTEGER,
  "TREE_INDEX"    INTEGER,
  "MODEL_CONTENT" NCLOB
);

-- 3. Train  (XGBoost / Hybrid Gradient Boosting Trees)
CALL _SYS_AFL.PAL_HGBT_TRAIN(
  TRIALS_TRAIN,    -- input data (must include label column)
  #PAL_PARAM_TBL,  -- parameters
  MODEL_TBL        -- ← model written here
) WITH OVERVIEW;

-- 4. Predict on new data
CALL _SYS_AFL.PAL_HGBT_PREDICT(
  TRIALS_TEST,     -- data to score
  MODEL_TBL,       -- trained model
  #PAL_PARAM_TBL,  -- scoring parameters
  RESULT_TBL       -- ← predictions written here
) WITH OVERVIEW;

Evaluation Metrics

MAE — Mean Absolute Error

MAE = mean( |y − ŷ| )

Average error in the same units as the target (dropout rate 0–1).

MAE = 0.08 means we're off by 8 percentage points on average — for a 200-patient trial that's ±16 patients.

Robust to outliers. Easy to explain to stakeholders.

RMSE — Root Mean Squared Error

RMSE = √mean( (y − ŷ)² )

Like MAE but penalises large errors more heavily.

If RMSE >> MAE, the model has occasional large misses on some trial types.

Use when big errors are especially costly.

R² — Coefficient of Determination

R² = 1 − SSres / SStot

Fraction of variance in dropout rate explained by the model.

  • R² = 1.0 → perfect prediction
  • R² = 0.0 → no better than predicting the mean
  • R² < 0 → worse than the mean

LLMs + In-Database ML

Two different roles — both essential

PAL / HANA (structured)

  • Trains on thousands of rows
  • Consistent, reproducible predictions
  • Explainable feature importances
  • Runs at query time in SQL
  • Data governance stays in DB

LLM (unstructured)

  • Understands free-text criteria
  • Generates embeddings for similarity
  • Explains predictions in plain language
  • Suggests retention strategies
  • Answers analyst questions in NL
